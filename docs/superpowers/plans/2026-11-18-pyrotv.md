# PyroTV Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Raspberry Pi kiosk appliance that shows a touch grid of fireworks and plays demo videos on the touchscreen or a connected TV, configurable from the touchscreen and from a phone over the Pi's own Wi-Fi hotspot.

**Architecture:** A Python FastAPI service (SQLite, ffmpeg, mpv, NetworkManager) serves a no-build vanilla-JS web UI. `sway` shows that UI in Chromium kiosk on the touchscreen (HDMI-A-1). Touchscreen playback uses the browser `<video>` element. TV playback is mpv on the second HDMI output, driven over its IPC socket. Hardware access (HDMI detection, mpv, audio sink switching, nmcli) sits behind small interfaces with fakes, so everything except the Pi-specific parts is developed and tested on a PC.

**Tech Stack:** Python ≥3.11 (FastAPI, uvicorn, Pillow, segno, pytest, httpx), SQLite, ffmpeg/ffprobe, mpv, sway, Chromium, PipeWire (`pactl`), NetworkManager (`nmcli`), vanilla JS ES modules, `node --test`, Playwright (e2e).

**Spec:** `docs/design.md`

## Global Constraints

- Hardware: Raspberry Pi 4B **1GB**, Raspberry Pi OS Lite **64-bit**, 10.1" 16:10 touchscreen on HDMI-A-1 (+ USB touch), optional TV on HDMI-A-2. Dev boards with more RAM run with `total_mem=1024`.
- UI language: **Swedish only**; all user-visible strings live in `frontend/js/i18n.js`.
- Backend is Python + FastAPI run by systemd; data in SQLite with `journal_mode=WAL` and `synchronous=FULL`.
- Videos are 1080p30 H.264 MP4 (CapCut exports). Catalogue video is `videos/<exact name>.mp4`, image is `images/<exact name>.jpg|.png` (name equals the catalogue name).
- Video library budget **40 GB** of a 64 GB SD card; used/free shown in Settings.
- Power loss must never need repair: root filesystem read-only (overlay), separate writable ext4 data partition at `/data`, uploads written to temp and atomically renamed, view counts flushed in batches (every 120 s and on shutdown).
- Hotspot only (no internet); **off by default**, switched on from Settings. The Wi-Fi password is an **8-digit PIN generated by the app each time the hotspot is switched on** and shown on the touchscreen (text + QR); optional auto-off timer.
- No separate admin login: whoever can reach the app can change settings. Only loopback (the touchscreen) and the hotspot subnet `10.42.0.0/24` are served; every other client gets 403.
- Audio: Pi 3.5 mm jack normally; HDMI audio while the TV is connected.
- No internet features, accounts, cloud sync, remote updates or multi-language support.
- Custom pieces belong to a manufacturer: an existing one, or a new custom one created at upload time. Custom manufacturers and pieces are stored with the catalogue data and behave exactly like built-in ones (wizard, enable/disable, categories, sorting).

## Review Focus

1. **Swedish names and filenames:** catalogue names with å/ä/ö whose video file was saved with a different Unicode form (NFD from macOS/Windows tools) or different letter case must still match; sorting must follow Swedish order (å, ä, ö after z).
2. **Power pulled mid-upload or mid-transcode:** no half-written piece may ever appear; stale temp files are removed at boot; the SD card is never left needing repair.
3. **TV unplugged during playback:** playback stops, the UI returns to the grid, audio switches back to the jack. TV plugged in during local playback does not disturb it.
4. **Stale or exposed access:** the hotspot PIN changes every time the hotspot is switched on, so the old PIN stops working; the hotspot is off after boot; requests from outside loopback and `10.42.0.0/24` (e.g. if the Pi is also on Ethernet) are refused with 403.
5. **Disk full / duplicate names on upload:** uploads are refused cleanly when free space is below size + 1 GiB; a custom piece whose name equals (case-insensitively, Unicode-normalised) an existing piece **of the same manufacturer** is rejected; deleting a custom manufacturer's last piece does not leave an empty manufacturer behind.
